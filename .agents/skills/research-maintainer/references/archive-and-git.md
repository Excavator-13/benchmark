# 封存、Git 与备份

本节动作按用户请求触发，不是每次收尾的默认清单；完成用户请求的范围即停止，见 [SKILL.md](../SKILL.md) 的“按请求停止”。

## 三种身份

| 身份 | 记录的事实 | 权威位置 |
| --- | --- | --- |
| 运行代码身份 | 执行源码基准 commit，加相关实际差异/脚本身份 | run provenance 和随运行保存的源码材料 |
| 产物内容身份 | 封存包的字节内容 | 保存它的地方：进了 Git 的包是那次提交，放在 Git 之外的包需要包外 SHA256 |
| 入库身份 | 哪次 Git 提交或持久存储操作保存了产物 | archive index、Git 历史或可核验的存储回执 |

本节是陈述纪律：不得用其中一种身份冒充另一种。它本身不要求任何操作；封存、入库、备份和恢复流程只在用户要求时按本文件后续步骤执行。

后续 commit 不会使运行代码身份失效；push 不改变已有 commit 的身份。提交纯文档或归档包不意味着运行应改记新 HEAD。反之，复跑时使用更改过的执行源码，就应记录新的实际来源。

不创建自指依赖：包内不包含包自身哈希，也不要求包内摘要包含保存该包的 commit。外部索引可以记录入库 commit，但不要求记录包含索引自己的最终 commit。

包已经在 Git 里时，那次提交就说明了它的内容，不用再加包外 SHA256 和成员清单。包放在 Git 之外（外部存储、单独拷贝、交给别人）时必须有包外校验——否则没有东西能证明它没被改过。清单里说明“哪些内容被有意排除”属于来源信息，不是内容身份，该留还得留。

## 运行开始时

记录实际执行仓库的 commit、分支及工作区状态。相关代码未提交也可以研究，但保存影响运行的差异、未跟踪执行脚本/配置和必要源码哈希；仅记录 HEAD 不足以重建脏工作区。不同机器、依赖或设备单列，不无证据声称与原环境相同。

记录协议快照、实际输入身份、运行配置、环境、精确命令/脚本和输出位置。报告 metadata 为历史快照，不随着后续提交滚动更新。

## 封存

1. 确认运行已结束或已中断，且没有进程继续写目录。仍在写入的产物保持 mutable；中断/失败也可在静止后封存。
2. 保存摘要、provenance、实际过程、输出及核验结果，检查该类型工作所需的材料。缺失明确写入限制，不能用全目录打包宣称可复现材料完整。
3. 使用唯一 run ID 和新包路径，拒绝覆盖同名封存产物。打包时排除缓存和操作系统元数据，保留重建结果需要的材料。包位于 run 目录之外。
4. 核验包成员及包内内容与源目录一致性。解包核验写入新的临时目录，不在现有运行目录上覆盖解压；检查成员不逃逸目标路径。包要放在 Git 之外时，再生成包外 SHA256。
5. 在 archive index 记录路径、内容身份（提交号或包外 SHA256）、核验时间和限制，标明 sealed。核验范围限于包字节、成员与源目录一致性，不扩展到远端取回或恢复测试。此时尚未提交则如实写尚未入库，不用将来时冒充成功。

封存之后追加分析保存补充记录并关联旧 run，更正指标或解释同样如此；只有当追加工作本身构成一次新的实验（新预测、改变条件或受控干预）时才建立新 run。发现旧包损坏时保留损坏事实和恢复来源，不能覆盖包并沿用原哈希。

## Git 入库

遵循用户对 commit 的已有授权。用户仅授权编写文件或 skill 时，不顺带提交其他工作；未授权 commit 时完成可检查的产物并报告待提交。

获得授权后：

- 查看当前工作区及暂存区，明确本次具体路径。已有用户改动和此前暂存项不被撤销或混入本次提交。
- 检查相关 diff、文件是否被跟踪/忽略、归档校验与应做的验证。小规模归档可随 Git 保存；较大产物使用项目已确定的持久存储策略，不能因仓库忽略而当作已备份。
- 仅提交本次授权范围，检查最终提交确实包含目标文件，并记录实际结果。避免宽泛 `git add .` 自动收纳运行目录和无关文件。
- 入库 commit 可以提交后再记入外部索引，后续索引提交不需要记录自己的 hash；也可直接从 Git 历史追溯。摘要无需为入库而改写。

例如包的入库历史可通过下面的只读命令检查：

```bash
git log --follow --format='%H %cs %s' -- research/archives/<run-id>.tar.gz
```

要核对具体提交包含目标包和校验文件，而非只找到一个相似提交标题。封存包如有多个不同内容版本，记录异常和对应身份，不任选一个提交作为唯一事实。

## 推送与异地备份

push/上传按用户明确或既有授权执行。备份是一个独立收尾任务；用户未授权时报告待处理，不把它自动扩成远端写入。

区分 `未核验 / 已确认尚未备份 / 已核验备份`。本地 remote-tracking refs 可能过期；不能仅靠缓存引用断言远端没有某个提交。

备份记录至少包含位置（远端及分支，或持久存储对象）、目标 commit/对象身份、核验时间和核验方法。网络不可用或未做独立读取时记未核验；没有实际取回或远端读取证据时，不声称已完成恢复测试。这一句是陈述规则，不构成执行恢复测试的义务——恢复测试只在用户要求时按其范围进行。

push 成功后可更新外部索引的备份状态。若索引更新尚未推送，明确产物已在远端、索引更新待同步。之后推送索引无需无限新增“这个索引自己的 push 回执”；备份身份指向目标产物提交，并带核验时间。

## 恢复与可读记录

将 RESEARCH.md、state、计划、决定、归档索引及小型摘要/来源/执行脚本纳入正常文档版本管理。产物包包含运行证据的封存副本；封存后可读摘要保持与副本一致，后续状态写在外部索引。

避免唯一入口只链接未跟踪的展开目录。若大型结果只存在包或外部存储，索引提供持久来源、校验和恢复说明。用户要求恢复核验时，新 clone 先核验来源和哈希，在独立位置恢复，按运行内协议/配置重算；不拿后来更新的计划替代运行快照。未要求时只记录已有位置和已知限制，不预先演练。

可读摘要缺失时先登记现有证据；从已核验的包取出的摘要标明来源。历史资料不完整时保留限制，不补写当时未保存的环境、commit 或命令。
