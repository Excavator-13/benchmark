# 接手、进度变化与规范化

## 接手

1. 读稳定入口、state、当前 phase plan 和影响下一任务的 decisions；按需读协议和对应 run，不默认重读所有历史日志。
2. 查看 Git 状态和实际产物，验证 state 的关键指针。未跟踪文件不一定丢失，已提交文件不一定有异地副本。
3. 核对阶段/任务验收与当前执行者、进程。state 写“执行中”但未找到进程时，检查输出和最后记录，标明执行状态待核验，不能直接改为成功或断言已中断。
4. 有冲突时记录具体冲突及证据。可以独立核实的先核实；只有无法推断且影响下一动作的事项才向用户询问。
5. 简短说明恢复出的当前位置，继续最新用户请求授权的工作。用户请求状态或讨论时不启动实验。

缺失交接材料时根据证据重建最小状态，并注明哪些是重建、哪些仍未知；不要假装前一会话已做了未被保存的工作。

## 开始和部分完成

任务首次实际执行时标为 in_progress，state 关联该任务和当前 run。准备环境、写提案、训练、核验等不同子任务按计划各自验收。

完成一部分后更新已完成步骤、输出链接和剩余步骤。重要结果立刻保存脚本/准确命令及输出；不能仅留下数字。没有达到任务验收则继续保留 in_progress，或按真实情况转 blocked/paused。

若用户要求暂时停止，确认实际进程如何处理并记录；记录暂停不意味着后台实验已经停止。结束交接时明确“agent 无人执行”与“外部进程仍运行”的区别。

不要将终端命令失败解释成科学结论。失败运行保存实际退出位置和产物，新尝试用独立 run，不覆盖前一次结果。

## 新发现和计划调整

- 将观察、解释与行动建议分开。证据不足或只有聊天记录时标为探索，保存可复查过程后再更新证据状态。
- 给重要建议创建 decision ID，写出它影响哪些任务以及能否改变协议；它不会因为出现在 agent 最终回答中而自动变成当前计划。
- 若预先制定的决策表或既有授权已经决定行动，可以记录该依据并执行，不要求用户重复批准。
- 接受改变工作顺序的建议后，更新 phase plan 的依赖和下一任务，记录原任务延期/取消理由，同时更新 state 指针。
- 科学定义、选模口径、数据边界或完成条件改变时，保存版本和决定依据。运行时协议快照不可覆盖，比较表标清兼容性；普通勘误也记录影响，不靠修改版本号掩盖差异。
- 阶段可以尚未完成而调整后续计划；结束阶段仍要逐项核对验收。主动终止阶段记 cancelled 和理由，不能通过删掉未完成任务把它改成 completed。

## 收尾检查

确认实际执行状态和产物；更新任务验收、state、decisions 和必要 archive index。计划中的实验保留待执行，不写成已完成。未执行的收尾步骤明确列出。

下一动作应具体到一个可执行步骤及其前置条件，不只写“继续科研”或“进入下一阶段”。用户尚未授权启动下一实验时，下一动作是准备/确认实验范围；列出动作不表示已经获得授权。

## 停止规则

本流程的边界：收尾记录以实用为准，不为了记录记录自身的提交、推送身份而无限追加文档提交；用户要求结束或停止时，停止本轮自行启动的额外检查并保存恢复点，不把取消的检查改写成以后必须补做的任务。

交接完成点和请求到停止点的对应表见 [SKILL.md](../SKILL.md) 的“按请求停止”，本节不重复其内容。

## 首次规范化已有项目

本 skill 的标准结构是目标，原目录只是待迁移的材料来源。遵循用户已经明确的整理授权，不把“初始化 skill”当作自动迁移所有项目的许可。

1. 盘点总计划、阶段计划/协议、当前状态、决策、指南、运行材料、归档包及 Git 跟踪状态。标明历史记录缺失或互相冲突。
2. 提供旧路径到标准职责/路径的具体映射，识别脚本、Notebook、文档、Git 忽略规则和外部机器中的路径依赖。明确本次迁移范围。
3. 先创建标准入口和权威状态，以证据重建当前子任务。若迁移已授权，可在同一次规范化中完成；未授权的搬移留为具体待办。
4. 当前可变文档迁入标准路径并修复引用；保留任务、决定和运行身份。封存包及内部文件保持原样，在索引登记 legacy 路径和来源。历史指南作为历史材料链接，避免成为另一份实时进度表。
5. 已有 legacy 包无需为满足新结构而重新打包。未来运行按标准创建；历史产物引用通过索引和迁移记录解析。
6. 在 `research/archives/migrations/<migration-id>.md` 保存旧/新映射、发生时间、验收依据、未迁移项及限制；检查文件内容、必要路径/命令和恢复能力。

用户明确要求新 agent 自动读取入口时，在项目代理入口（例如已有 AGENTS.md）增加指向 RESEARCH.md 的接手约定；此项属于明确的初始化/规范化范围，不靠 skill 可用就声称每次会话必然加载。

一次组织迁移不同时修改科学模型和评估定义。迁移可独立提交；Git 操作仍使用本次及既有授权。规范化未全部完成时，RESEARCH.md 标明过渡状态和旧材料映射，之后继续完成标准化，而不是永久改写 skill 去迁就旧路径。
