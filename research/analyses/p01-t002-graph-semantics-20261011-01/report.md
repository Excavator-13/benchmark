## 方法

只用原始 Parquet。节点键为上下文 ID + `skill_id`，按规范顺序排序。边为上下文内的有向行 `(row_id, col_id)`：

- `out_degree` = 节点在其上下文内作为 `row_id` 的不同 `col_id` 数（去自环）；
- `in_degree` = 作为 `col_id` 的不同 `row_id` 数；
- `undirected_degree` = 无向化后（`min/max` 去重）的相邻节点数；
- `reverse_edge_ratio` = 非自环有向边中，同一上下文内反向边 `(col_id, row_id)` 也存在的比例；
- 覆盖 = `undirected_degree > 0` 的节点占比。

端点匹配、非自身邻居覆盖与 `r0`/`region` 的 `covered_nodes` 与 T004 已存 `coverage.json` 一致（脚本内断言/比对通过）。另附一个明确标注的"跨上下文技能投影"统计，只用于解释历史预分析，不是预测图。

### 历史预分析的解释（明确标注为跨上下文技能投影，非预测图）

历史[多粒度共现图统计分析](../../archives/legacy-exploration/多粒度共现图统计分析.md)报告 `r0` 权重均值 2.00、`region` 7.20/中位数 6/最大 14/≤2 占比 21.5%。本轮按同样"丢掉上下文、方向相加"的口径重算，得到：

| 投影指标 | r0 | region |
| --- | ---: | ---: |
| 不同技能数 | 314 | 314 |
| 不同无向技能对 | 30,402 | 30,402 |
| 每对跨上下文有向行数：均值 / 中位数 / 最大 | 2.00 / 2 / 2 | 7.198 / 6 / 14 |
| 每对计数全为偶数 | 是 | 是 |
| 计数等于 2 的占比 | 100% | 21.49% |

这与历史报告逐项吻合，说明历史"权重"是**跨场景出现次数再乘 2**（每个有向对都同时以两个方向出现），不是广告共现频率，也不是可区分强弱边的连续分数。`r0` 只有一个上下文，所以每个技能对恰好出现 2 次（两个方向），历史所称"图信息完全丢失"实为单一二值边在多上下文下的重复计数现象。历史报告的 314 节点也只是"出现在边里的技能数"，不是任务节点全体（`r0` 2,335、`region` 16,345）；在上下文限定口径下 86.6% 的任务节点是孤立节点。

## 限制

- 本分析只描述发布图的静态结构，不解释模型为何表现好或差，也不证明"稀疏节点依赖邻居"一类因果假设。
- 投影统计仅供解释历史材料；各粒度预测图仍以上下文限定节点为准，不能沿用 314 节点的技能投影做建模或覆盖论证。
- 未引入时间维度；图构建时间来源另见 T002 第 4 项结论。
- 结果只覆盖 `r0/count`、`region/count`；`r2/count` 的完整同流程审计归 P01-T006。
