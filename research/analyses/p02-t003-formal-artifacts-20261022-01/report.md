## 方法

1. **身份**：逐 run 计算两份 artifact 的 SHA256，与 checks 的 `input_sha256_after` 比较；90×2 份全部必须一致。
2. **训练历史**：检查 200 epoch、每 epoch 一步 Adam、最优 epoch、`selected_validation_MSE` 与 checks 重算的验证 MSE 一致。
3. **输出上限**：由 `head` 权重直接算出模型对任意输入可产生的最大预测绝对值。自身分支 `|ŷ| ≤ max_h(Σ_i|W[h,i]|+|b[h]|)`（GRU 末隐状态为 tanh，`|h|≤1`）；图/打乱分支的隐状态为 `h + mean(h_u)`，上界翻倍。
4. **MAE 地板**：任何满足 `|p| ≤ B` 的预测都有 `E|y−p| ≥ E|y| − B`；`E|y|` 就是 `Zero` 基线的 MAE（checks 已给出）。据此得到 MAE 的理论最低值，与实测 MAE 比较。

## 结果 1：180/180 artifact 与检查记录一致

90 个 run 的两份文件全部匹配 checks 记录的 SHA256，无缺失、无不一致。90 份 history 均为 200 epoch、每 epoch 1 步、最优 epoch 200，且 `selected_validation_MSE` 与 checks 重算的验证 MSE 一致（脚本未记录任何问题）。权重、训练历史与检查指标三者互相印证，说明这批上传件就是 T002 正式 run 的原件。

## 结果 2：训练在 200 步内基本没有移动

各组验证 MAE 从第 1 epoch 到最后 epoch 的变化：`r0` 约 1042.6→1036.4（−0.6%）、`region` 约 149.0→145.2（−2.5%）、`r2` 约 20.1→19.1（−5.0%），且全部选择第 200 epoch（仍在改善）。这是正式 run 的直接证据，与之前从 smoke run 得到的判断一致。

## 结果 3：输出上限把 MAE 压在 `Zero` 基线附近

由权重算出的上界与地板（按 dataset/method 汇总，9–30 个 run 的范围）：

| 组 | 分支上限 | Zero MAE | 地板 | 实测 MAE | 实测离地板 | 相对 Zero 的最大可能收益 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| r0 / self | 8.60–9.06 | 1165.37 | 1156.31 | 1158.61–1159.09 | 2.0–2.5 | **0.78%** |
| r0 / graph | 17.49–18.19 | 1165.37 | 1147.18 | 1158.67–1159.11 | 10.8–11.5 | 1.56% |
| r0 / shuffled | 17.49–18.20 | 1165.37 | 1147.18 | 1158.67–1159.11 | 10.9–11.5 | 1.56% |
| region / self | 8.64–8.92 | 166.48 | 157.56 | 162.50–162.74 | 4.7–5.0 | 5.36% |
| region / graph | 17.32–18.10 | 166.48 | 148.38 | 162.89–163.16 | 13.8–14.5 | 10.87% |
| r2 / self | 8.56–8.81 | 22.41 | 13.60 | 21.42–21.49 | 7.6–7.8 | 39.33% |
| r2 / graph | 17.08–17.55 | 22.41 | 4.86 | 21.62–21.69 | 16.3–16.8 | 78.30% |

（图/打乱两行上限相同，因为隐状态上界都是 2；shuffled 与 graph 的地板相同。）

要点：

- **r0 自身分支的输出范围本身就排除了 1% 门槛**：即使把输出用到极限，MAE 最多只能比 Zero 好 0.78%，低于 §6.2 的 1% 要求；实测值离这个地板只差 2–2.5。图分支的上限允许 1.56%，相对自身约 1.0%，但实测差距只有 0.002%–0.003%。
- **region / r2 的上限允许更大空间，但实测离地板很远**（5–17 MAE）：模型并没有用满自己的输出范围，是"没学动"而不是"学满了但没用"。r2 尤其明显——图分支地板 4.86，实测 21.6，仍在 Zero（22.4）附近。
- 因此 T003 的"训练未发生、图对照无信息"判断在正式 run 上得到核验；同时也说明 r0 的门槛失败不能单独归因于图语义。

## 结果 4：还差多少个数量级（步数估算）

由 90 个 run 的 head 权重还能读出"离收敛有多远"的量级。PyTorch `nn.Linear` 默认初始化下，每行 L1 的期望约 2.9；训练后实测每行 L1 为 7.0–9.0（均值 8.24），即 200 步里每个元素平均增长 0.17（约 `8.35e-4`/步，**相当于 lr 的 83%**）——优化器基本一直贴着 Adam 的步长上限在走。

| 数据 | 目标量级（测试均值） | 当前 head L1 | lr=1e-3 所需步数 | lr=1e-2 所需步数 | 30 次拟合外推耗时（lr=1e-3） |
| --- | ---: | ---: | ---: | ---: | ---: |
| r0 | 1165.4 | 8.24 | ~43,500 | ~4,350 | ~106 h |
| region | 166.5 | 8.24 | ~6,100 | ~610 | ~72 h |
| r2 | 22.4 | 8.24 | ~730 | ~73 | ~57 h |

这是按"把输出均值推到目标量级"线性外推的数量级估计（不含学会输入映射；图分支上限翻倍，可把步数减半），耗时用各 run `summary.md` 的实测 Total 除以 200 步外推。三组一起，若只加预算不改尺度，`lr=1e-3` 需要约 10 天量级的拟合时间；`lr=1e-2` 约 1 天但原始 count 的 MSE 配大 lr 有稳定性风险。这说明"再多跑一会儿"不是免费的，缩放目标尺度是更实际的路线。

## 限制

- 上界是精确的，但只约束输出幅度，不替代逐预测检查；本机没有 torch，未重跑 GRU 前向，也未重算完整预测分布。
- 地板用三角不等式得到，依赖 `E|y|` = `Zero` MAE 与 `|p| ≤ B`，是必要条件而非可达值；个别 horizon/分组的实际最低值可能更高。
- 未验证上传分支中仅换行差异的 106 个文件；它们不属于本次导入范围（见 D034）。
- 不改变 T002 的验收结论，也不证明"训练好的模型一定没有图收益"；它只说明冻结的 200 步预算下这批对照无法回答该问题。
