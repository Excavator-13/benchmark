## 1. 这一阶段需要回答的四个问题

1. 预测对象、图节点和边权到底是什么？
2. 在完全相同的预测窗口上，不使用图的简单方法能达到什么水平？
3. 当前 EvolveGCN-H 的波动来自哪里，哪些部分可重复？
4. 本地开发需要多少时间和内存，哪些工作才需要 GPU？

完成后应能明确说出“我们在这个协议上有一个可信的参照”。不要求这个参照是最强模型，不要求复现论文全部数字，也不要求已经实现新方法。

## 3. 固定实验协议

本文件第 3 至 6 节是协议的唯一规范来源，包含数据与信息边界、预定分组、基线定义、指标、收益判据和记录规则。路线图讲研究方向，操作指导实现这里的定义；两者不能另定一套协议。运行时记录科学协议和保存政策版本，并按 §6.1 定位执行时内容；科学定义改变后递增科学版本，不覆盖旧运行。

### 3.1 节点身份和信号

每一行时间序列保留原粒度的上下文身份：

| 数据 | 节点键 | 当前数据预览中的节点数，运行时重新核对 |
| --- | --- | ---: |
| `r0` | `(r0_id, skill_id)` | 2,335 |
| `region` | `(region_id, skill_id)` | 16,345 |
| `r2` | `(r2_id, skill_id)` | 121,420 |

节点按上述键升序排序，与 `prepare_graph_data.py` 的规范顺序一致。不得把同一技能在多个地区或职业中的节点合并后，再与原粒度的模型结果比较。

现有预览的行数与“技能集合 x 上下文集合”的完整网格吻合：`r0=2335 x 1`、`r1=2335 x 14`、`r2=2335 x 52`、`region=2335 x 7`、`r1-region=2335 x 14 x 7`、`r2-region=2335 x 52 x 7`、`company=2335 x 521`。这意味着任务可能包含大量没有需求的组合，而不是只保留出现过需求的节点；相同技能在不同上下文中的需求序列并不相同。

完整笛卡尔积需要逐表确认节点键唯一、`skill_id.nunique()`、各上下文 ID 数、上下文组合数、各上下文技能集合及预期网格大小。README 的 2,324 与预览的 2,335 不一致，技能数以当前文件审计为准，不能仅凭行数倍数确定。全零序列比例和图覆盖率也必须实测，不能从网格大小推断“绝大多数全零”或“低覆盖必然”。

先使用 `dataset/demand/*.parquet` 的原始 count。时间列必须为连续的 2021-01 至 2023-12，共 36 月；所有值有限且非负，节点键唯一。`rate` 作为后续扩展，不能与 count 指标混合。

### 3.2 预测窗口和划分

输入长度 `L=6`，预测长度 `H=3`，单位步长为 1 月，共 28 个窗口。以 0 为第一个窗口起始索引：

| 划分 | 窗口起始索引 | 数量 | 目标月份 |
| --- | --- | ---: | --- |
| 训练 | `0..18` | 19 | 2021-07 至 2023-03 |
| 边界省略 | `19, 20` | 2 | 不用于训练或验证 |
| 验证 | `21` | 1 | 2023-04 至 2023-06 |
| 边界省略 | `22, 23` | 2 | 不用于验证或测试 |
| 测试 | `24..27` | 4 | 2023-07 至 2023-12 |

训练观察截止 2023-03，验证预测起点为 2023-03 月末；首个测试预测起点为 2023-06 月末。后续测试起点使用当时已经发生的真实历史，是滚动预测，不是从六月一次性预测全部未来月份。

这是为与修复版对齐而固定的划分选择：省略 4/28 个窗口，使不同划分的目标月份互不相交；它不是所有时间序列评测唯一合法的划分。其他选择需要独立协议和配套对照，不能悄悄混入这一版。

输入月份可以重叠，也可以包含先前划分已发生的目标月。验证窗口的输入为 2022-10 至 2023-03，包含训练目标月份；首个测试窗口的输入为 2023-01 至 2023-06，包含验证目标月份。它们在各预测起点已是观测，不构成未来信息泄漏。协议保证的是目标月隔离和起点信息可用，不是输入与历史标签完全不相交。

训练标签截到 2023-03，模型参数随后固定；2023-04 至 2023-06 的真实观测会作为测试输入被看到，但不用于重新拟合参数或标准化。之后测试起点滚动更新输入，仍不在线重训。

### 3.3 状态、预处理和选模

朴素基线和 Ridge 每个窗口独立预测，不携带窗口间隐藏状态。EvolveGCN-H 对齐旧结果时保留当前规则：每个 train/validation/test 遍历从初始权重开始，遍历内按时间传递状态。

冷启动与历史预热都是可定义的协议选择。若研究预热，另列配置，只使用预测起点前的输入、禁止更新参数或读取未来标签，并让相关对照使用相同规则。

学习模型仅使用训练样本拟合参数，使用验证集原始单位 MSE 选配置或 checkpoint。这样保持与当前图 runner 的平方误差训练和选模口径一致；MAE 是研究推进的首要误差指标，RMSE 同时衡量大需求节点的误差，选模指标不必等同于主报告指标。每个候选都记录验证 MSE 与 MAE，不能依据测试 MAE 重新选择候选。若以后改用验证 MAE 选模，另立协议并对相关模型一起重跑。

标准化的月份范围固定为整个训练观察期 `2021-01..2023-03`，每个节点恰好 27 个值，各月只计一次，包含最早的 6 个输入月份。禁止仅使用训练目标月、对重叠窗口重复计数，或加入验证/测试月份。均值与 `ddof=0` 标准差在此计算后冻结；输入和目标使用同一组节点统计量，常数节点标准差设为 1。内部回测则按各折的拟合观察期重新计算。

## 4. 数据审计：重新建立事实，而不是先解释模型好坏

### 4.1 时间序列审计

记录每组数据的节点数、技能数、上下文数、网格完整性、月份、ID 列、数值范围及每月非零占比。分别统计训练 27 月全零比例和完整 36 月全零比例；后者仅是描述性诊断，不用于分组、筛节点或调参。另记录常数节点、大需求节点和各组的绝对/平方误差贡献。

若全零组合很多，整体均值可能被大量小误差项稀释；但 RMSE 也可能主要由少数大需求节点的平方误差决定，不能笼统称为“零质量主导”。跨粒度的网格大小、活跃度构成和数值尺度是结构性混淆，设计阶段就需控制，不能只在最终讨论中解释。

分组默认使用训练观察期内的非零占比：`activity_i = mean(y_i,2021-01:2023-03 > 0)`。建议把它称为“活跃度”；若称为“稀疏度”，使用 `1 - activity_i`。

本协议固定四组：`activity=0`、`0<activity<=1/3`、`1/3<activity<=2/3`、`2/3<activity<=1`。边界各粒度相同，不按测试结果或本粒度分位数重新划分。保存每组节点数与掩码，空组明确标记。

除完整网格 MAE/RMSE 外，预先报告等权活跃度组 MAE（非空组 MAE 的算术平均）、各组相对指定 baseline 的改善率，以及各上下文的结果。跨粒度主要比较同组的相对改善，不直接拿原始 MAE 大小证明粒度效应。等权组指标控制报告构成，第一版训练损失仍保持原定义；加权训练是后续单独标记的敏感性实验，不混入主配置。

### 4.2 图审计

使用 `prepare_graph_data.py` 的上下文列定义。保留上下文、`row_id`、`col_id`，分别检查：

- 完整上下文内的精确重复行数，以及对应的权重分布。
- 定向边数、反向边是否存在、自环数和每个场景的边数。
- 源图端点是否全部匹配时间序列节点。
- 图中有边的节点占全部任务节点的比例、孤立节点比例和场景内度分布。
- 只有在明确写成“跨场景投影图”时，才另外统计丢掉上下文后的技能图。

发布图没有独立的 frequency 列。精确重复次数是数据能提供的 multiplicity，不能无证据升级成广告共现频率。如果权重全是 1，就明确记录“当前图不提供可区分强弱边的频率”。

后续边过滤的方向是过滤弱边、保留强边。本阶段只核查边分数能否支持这种区分，不学习过滤阈值；可学习阈值或软门控的具体形式留到方法设计阶段。

原始广告和图构建截止时间不齐全时，将固定图的时间来源列为未决信息。尤其不能把由较晚训练期构建的图直接用于较早回测，并宣称没有未来先验信息。

### 4.3 模型是否使用了图

在同一输入、参数和递归初始状态下，比较真实邻接与替换邻接后的输出。测试每次开始前重置状态，排除 Dropout 等随机因素；不能使用空输入或完全相同的节点特征作为唯一探针。

重点检查当前 `GConvLSTM(..., K=1)`、`GConvGRU(..., K=1)` 等配置。按 Chebyshev 卷积定义，`K=1` 仅有零阶项；核实安装版本和实际执行行为后，将其标记为原配置或无邻居传播配置。`K>=2` 是另一个需要验证和记录的配置。

审计产出首先描述数据与代码行为，不直接给出“粗粒度图一定是噪声”“稀疏节点一定依赖邻居”等因果解释。

## 5. baseline 的具体定义

### 5.1 五个无需优化训练的基线

| 名称 | 对每个节点、每个预测起点的行为 |
| --- | --- |
| Zero | 未来 3 月都预测为 0 |
| LastValue | 未来 3 月都预测为输入窗口最后一月 |
| WindowMean6 | 未来 3 月都预测为输入 6 月的均值 |
| TrainMean27 | 每节点取 2021-01 至 2023-03 的 27 月均值，所有预测起点和三步都用该冻结均值 |
| SeasonalNaive12 | 每个目标月预测为该节点去年同月的值；目标月索引为 `t` 时取 `t-12`，不是把去年最后值复制三次 |

它们没有 seed，无需优化器训练；TrainMean27 只估计冻结的训练期均值。验证和测试的去年同月值都在相应预测起点以前可获得。内部回测中 TrainMean 使用各折拟合观察期的均值，名称与月份数相应标记。

五项全部报告。以验证 MSE 在预定五项中选出 `NaiveRef`，平局按本表顺序选择，冻结后用于测试上的相对改善比较；不能取测试最好的朴素基线作为事后门槛。Ridge 只有胜过这个参照或在预定分组中显示优势时，才有“比便宜规则更强”的证据；仅可重复不意味着更强。

SeasonalNaive12 使用超出最近 6 月的历史，因此标记为“额外历史参照”。同时从其余四项按相同验证规则确定 `NaiveRef6`，用于输入长度为 6 的比较。TrainMean27 是从训练期估计的冻结节点统计量，不在预测时读取新的额外历史。NaiveRef 提供实用预测门槛，NaiveRef6 提供对应信息预算的参照；图的机制证据仍以相同输入和时序编码器的对照为准。

### 5.2 共享 Ridge：主要的稳定学习参照

每个节点只用自身 6 月历史，输出未来 3 月；所有节点、所有训练窗口共享一个 `6 x 3` 权重矩阵和 3 个偏置。它通过跨节点共享参数获得训练样本，但不使用图或其他节点的当前输入。

建议主配置：

- 按第 3.3 节的固定 27 月观察期计算节点均值和总体标准差（`ddof=0`），将输入和目标标准化；常数节点标准差设为 1。
- 在上述 19 个窗口上拟合多输出 Ridge，包含截距，截距不正则化。
- 优化目标为 `(1/M) * sum_m ||x_m W + b - y_m||_2^2 + lambda * ||W||_F^2`，即每个样本三步误差的平方和按样本数平均。预设 `lambda` 候选为 `1e-4, 1e-3, 1e-2, 1e-1, 1`。
- 仅由验证窗口的原始单位 MSE 选 `lambda`；相同时选择更大的 `lambda`。
- 预测逆变换后，在原始单位计算指标。主结果保留原始输出，非负裁剪作为单独标记的附加结果。

如果使用 sklearn 的 `Ridge`，其目标使用残差平方和，需传入 `alpha = lambda * M`，其中 `M` 是训练样本数，才能对应这里的平均损失定义。标准化和 lambda 定义必须写入结果元数据。

求解使用确定性的 CPU 线性代数。重复运行重点检查预测和指标是否一致，不能把浮点精度范围内的差异当作初始化方差。

后续可比较原始尺度或 `log1p` 配置，但第一版先只实现一种明确的主配置。共享 Ridge 不是每节点分别拟合的 Ridge，结果名称要体现这一点。

### 5.3 运行便利性的验收

先实测每个数据集的读取、拟合和推理耗时，以及峰值内存。报告环境和机器，不给未经测量的“Mac 几分钟能跑完”承诺。

Ridge 不应导入图模型 `main.py`，否则会无意要求安装整个 PyG 依赖链。先通过 Pandas/PyArrow/NumPy/sklearn 完成独立入口；图方法仍使用其原环境。

若扩展到更大的粒度，可分块积累线性回归统计量、分块推理。是否需要优化由测量决定，不在小数据阶段先引入复杂的缓存和并行系统。

## 6. 指标与结果文件

主指标采用所有测试窗口、节点和 horizon 的 MAE，以及先平均平方误差再开根号的 RMSE。不能把逐窗口 RMSE 的均值当作总体 RMSE。

同时报告：逐窗口 MAE/RMSE、各 horizon 指标、训练期活跃度分组、有邻居/无邻居分组、负预测比例。训练期全零组单列，防止零预测的优势被总体指标掩盖。

所有方法使用同一份训练期分组掩码，并报告第 4.1 节的等权组 MAE。每个模型记录验证 MSE/MAE、总体测试 MAE/RMSE、分组指标和各项样本数；不能只保留对自己有利的指标或分组。

四个测试窗口覆盖六个目标月，其中月份出现次数为 `1, 2, 3, 3, 2, 1`。主结果保留这个口径以对齐现有实验；若添加按月均衡的指标，明确公式并另列，不从重复窗口中构造虚假的独立样本数量。

初期不把 SMAPE 或论文 RRMSE 作为核心选模依据；它们对零值、分母定义和聚合方式敏感。需要与论文比较时，另行核对公式和零值处理。

### 6.1 实验记录与产物保存

完整产物要求适用于模型实验、改变条件的受控诊断和时间回测。一次实验围绕明确研究问题和执行条件组织，可包含多个方法与多条步骤；需要比较的独立重复执行保留各自身份和结果。确定性朴素 baseline 也是实验。普通检查、软件测试和记录维护不因执行命令或读取真实数据而成为实验。

实验使用独立且不覆盖旧结果的 `research/runs/<run-id>/`，至少记录：目的与所属任务；执行代码 commit 及影响实验的未提交差异和必要脚本；科学协议与保存政策版本及可定位内容；数据版本或内容身份；解析后的配置、关键依赖与环境、准确命令和实际步骤；耗时、设备与峰值内存；成功、失败或中断状态；主要结果与限制。

正式预测结果保存足以重算全部所报告指标的预测、标签、节点/时间/划分身份、固定分组掩码，以及被选模型参数、必要预处理统计和训练/选模记录。多个方法可共享标签和身份。保留全部候选的验证分数与选择理由；落选候选的完整参数和预测仅在研究需要时保留。原始单位、裁剪结果和各项分组报告要求不变。

Git 中已有的源码和协议用固定 commit 加相对路径定位，无需逐次复制。共享的数据清单和来源材料允许引用固定版本。执行内容尚未提交时，保存影响实验的 patch 和必要未跟踪源码/协议内容，不复制无关文档或整个测试目录。来源 commit 不随 HEAD 更新；材料缺失时记录对复现和结论的具体限制，不追溯伪造。

指标重算、重复结果比较、旧结果对齐等检查保存简洁报告，包含被检查对象与必要输入身份、检查脚本/来源版本、命令、结果和容差。开发检查由开发/独立验证记录承载，实验检查归属相应实验；不自动创建独立科研 run 或复制完整来源与环境。新分层或图分布分析保存问题、输入与脚本版本、步骤、表/图和限制，可使用独立分析文档；产生新预测或执行受控干预时按实验记录。封存后补充报告放在外部并链接原实验。

实验材料可直接以文件保留，确有需要时再打包。小型摘要、配置、指标、选择记录及必要产物可纳入 Git；大型产物按已确定的持久存储位置保存并在[索引](../../archives/index.md)定位。临时 fixture、测试和开发探针使用忽略的 `scratch/` 或系统临时目录。失败/中断实验保留已形成的记录和有价值产物，普通开发失败无需完整封存。

进了 Git 的包以保存该包的提交作为内容身份，不再要求包外 SHA256 或全成员哈希清单。包位于 Git 之外时保留包外 SHA256。打包排除缓存、系统元数据或其他内容的声明属于来源信息，必须保留，不能随着哈希清单一起删除。旧封存包及包内清单保持不变；包外索引和冗余校验可按新政策整理，历史核验报告保留原结论与范围。

实验完成按执行与科研验收判断，不以打包、逐文件校验、commit、push 或远端恢复演练为完成条件。支持正式结论的必要材料有明确保存位置；只有本机副本时如实说明，不冒称异地备份。Git 和备份动作按用户授权执行，push 请求在正常推送成功后结束；恢复核验仅按明确请求执行。

现有 `python -m benchmark.nograph_baseline run` 已支持 `r0/count` 和 `region/count`，见[执行指导 §7](execution-guide.md#7-当前可复用-baseline-入口)。保存格式与检查输出调整已获 [OpenSpec 归档 PASS](../../../openspec/changes/archive/2026-10-08-reduce-baseline-evidence-overhead/verification.md)及 [D011 研究侧接受](../../decisions.md#d011-t010-记录减负研究侧验收)。旧图 CLI 的 `benchmark/graph_method/results/` 仍是忽略路径。

### 6.2 可执行的重复性与收益判据

下面是预设的工程推进门槛，不是统计显著性检验，也不是领域公认阈值。修改时应在查看新的最终比较结果前更新协议版本。

1. 同 seed 重复至少两次。用 `abs(MAE_a-MAE_b)/max(1, MAE_a, MAE_b)` 计算差异，CPU 要求不超过 `1e-6`、CUDA 不超过 `1e-4`；同时记录预测最大绝对差。超过时先调查执行条件，不能将其直接并入初始化方差。跨设备重复单列。
2. 开发筛查使用预定 seed `0,1,2`；最终重点配置使用 `0..4`。比较相同数据、协议和 seed 的配对误差，确定性基线在每对中复用相同预测，不生成伪 seed 方差。
3. 在一个预先指定的数据集和指标上，以 `gain_s=(MAE_ref_s-MAE_candidate_s)/MAE_ref_s` 定义收益。开发推进要求至少 2/3 个 seed 为正、收益中位数至少 1%；最终称为该固定评测期的稳定收益要求至少 4/5 为正、收益中位数至少 1%，且至少为同 seed 重复收益差异的 5 倍。参照 MAE 为 0 时不计算改善率；不能声称在 MAE 上进一步改善。
4. 图有额外价值要求真实图相对自身分支和预定的结构打乱对照均满足上述门槛。打乱图预设三个 seed `0,1,2`，按每个模型 seed 的三图平均 MAE 构造该对照，不挑最弱的图。记录是否成功保留场景内度分布及充分改变边。
5. 整体改善主张还要求总体 RMSE 的跨 seed 均值相对指定参照恶化不超过 1%。只有预注册分组达到门槛时，结论限定为该组，并同时报告完整网格结果和其他组的代价，不能升级成整体改善。

跨时间稳健性另外要求至少两个合法的开发回测中平均 MAE 收益都为正；图构建时间不可确认时，先限制为固定评测期证据，不以种子重复宣称时间泛化。种子标准差只描述初始化，不代表对未来月份的置信区间。

不将数万个节点或重叠窗口视为独立样本来做配对 bootstrap。可选的探索性区间应保留场景内节点和整段时间误差的相关性；Region 仅有 7 个上下文、r0 只有 1 个，加上很短的时间段，通常不足以给出可靠的总体显著性主张。更强的推断需要更多独立时间段、场景或数据集。

## 7. 诊断已归档的 EvolveGCN-H

原始结果目录是 `experiments_archive/1st_try_in_phase_fix_origin/benchmark/graph_method/results/count/region/EvolveGCNH/`，训练提交为 `950a1d8febbf992b8bda061d35f03107d0b18478`。

执行顺序：

1. 重算归档预测的 MAE/RMSE，确认与 `metrics.json` 一致。
2. 核对两个 seed 的标签，及标签与规范排序后的原始数据窗口。
3. 对同一标签计算五个朴素基线，报告逐窗口和逐 horizon 结果，并使用验证选定的 NaiveRef。
4. 条件允许时，在原提交、同数据、同依赖和同设备上复跑 seed 1，使用独立输出目录。
5. 同 seed 稳定而不同 seed 差异较大时，再补 seed 2、3、4。

如果更换 GPU、依赖或提交，结果仍可研究，但标记为跨条件重复，不据此认定原运行不能复现。若无法恢复旧环境，保留这个限制，直接为新环境建立自己的确定性记录。

若模型不如朴素基线，先查看误差集中节点、负输出、输入尺度、TopK 饱和和测试冷启动。每次只改变一个因素。不要立刻增加层数或补大量 seed 来掩盖问题。

输入归一化、学习率和状态预热的实验需单独命名。当前 CLI 不支持学习率、层数或 results_dir 参数，不能在命令中虚构这些选项；参数化需要后续开发，独立目录可通过现有 Python API 配置。

## 8. 少量时间数据下的验证策略

单一验证窗口能用于第一轮对齐，但不足以支撑稳定性主张。主要学习基线完成后，在训练观察期内部增加两个开发回测：

| 回测 | 拟合观察期 | 验证目标 | 开发评估目标 |
| --- | --- | --- | --- |
| A | 2021-01 至 2022-06 | 2022-07 至 2022-09 | 2022-10 至 2022-12 |
| B | 2021-01 至 2022-09 | 2022-10 至 2022-12 | 2023-01 至 2023-03 |

每折重新构造窗口、拟合标准化和模型。它们是开发证据，不是额外盲测，也不是独立同分布的重复试验。最后的 2023-07 至 2023-12 仍保持主协议。

这一步先用于无图 baseline。图模型需要确认先验图在回测截止时可获得；无法确认时，不把固定发布图用于这些折的结果解释为严格历史回测。
