# P02-T005 新训练条件与成本方案

日期：2026-11-07，Asia/Shanghai。任务：P02-T005。类型：方案制定与现有能力核对，不是实验 run。
范围：依据 D037，形成 GRU/LSTM 有效学习方案、有限选择范围、成本门及软件交接。科学定义的唯一新增规范为 [P02 协议](../../phases/P02/protocol.md) `P2-effective-training-L6-H3-v1`；任务状态与验收由 [P02 计划](../../phases/P02/plan.md) 维护。

## 1. 判断与依据

优先处理输入／目标与输出的尺度匹配，同时把训练预算明确为参数更新与样本覆盖。上一批训练欠拟合已有 [正式 run 权重与历史核验](../../analyses/p02-t003-formal-artifacts-20261022-01/report.md) 支持；本轮直接引用，不重跑该核验，也不把其线性外推耗时当作新方案测量。

选用训练期统一 RMS 缩放，而非直接以逐节点标准化目标 MSE 训练，是为了先保持原始需求的相对损失权重。统一缩放也不注入训练均值作为预测偏置，便于解释新的自身／图对照。Ridge 的逐节点标准化已有实现，但不能不加区分地接到这批神经模型上；如将来研究逐节点缩放，需说明训练目标权重与均值基线的变化。

每次更新改为一个完整训练窗口，窗口内全部上下文先积累再 step，可增加单位样本遍历的更新次数，并保留图聚合需要的完整上下文。这与旧全批量更新是不同优化轨迹，不能将新结果改善单独归因于尺度。新的更新／遍历／验证／checkpoint 语义均由协议显式定义。

训练有效性与模型排名分开：先确认学动且未明显受预算末段限制，同时完整报告 LastValue/Ridge。有效学习不保证图收益，固定融合负结果也不代表所有图架构无效。本轮没有新预测或新图收益结论。

机器尚未由用户选定。建议 Mac 用于本地开发检查，Windows 若仍保有可用环境则可承担较大批次；实际训练前按协议资源档位校准。首批 CPU 设计不依赖 Apple MPS、CUDA 或特定 CPU 型号，换机须记录环境身份并重新测成本，不能把跨设备差异当同条件重复。

下一步为 T006 的软件准备。建议 OpenSpec 对象名 `add-effective-temporal-training`（仅预留，未创建、未登记在途委托）；交接只需引用本报告与新协议，不复制成另一套科学定义。

实现边界与独立验收至少覆盖：

1. 新协议与旧计算身份隔离；显式解析编码器、尺度、优化／预算和资源配置，不通过修改原冻结模块全局常量或旧 run 绕过。

3. 一个训练窗口内按全体元素分母积累上下文梯度、然后裁剪／更新；轮／步计数与完整上下文图兼容；GRU/LSTM 状态重置、参数量及同 seed 起点可核对。

7. 原 runner 行为不被新协议静默替换；实现／独立验证使用 fixture 与开发输出，不以本次正式三组训练替代软件验证。
